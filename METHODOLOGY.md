# Frozen inference methodology

Inference begins from normalized S1 name, address, and country. It builds the approved country-aware exact-name, prefix, significant-token-pair, word, and numeric-address blocking keys. Base postings over the fixed cap are skipped. It then examines the two least-frequent eligible address tokens and applies the frozen rare-address overlap checks; if that candidate pool exceeds its fixed bound, the rare route is discarded for that S1. Up to 25 qualifying rare-route additions are ranked using the existing float32 feature ordering after removing baseline candidates.

The matcher computes the canonical 39 float32 features: the original 26 base features, numeric exact/conflict, route metadata, containment/trigram/script features, and three ICU transliteration features. ICU 77.1 applies `Any-Latin; Latin-ASCII`, followed by the existing name normalization. All four existing 39-feature B-cross-script fold models score every candidate. Their probabilities are averaged arithmetically. The numeric-conflict feature selects the frozen 0.99 threshold; otherwise the threshold is 0.98. At most 11 targets are emitted, ordered by score. Every candidate list written to `candidate_pairs.tsv` is the exact candidate set passed to the matcher after `top_25`.

No retrieval, feature, model, ensemble, threshold, or match-cap changes are made by this deployment. Parallel workers own disjoint canonical S1 ranges and separate output/checkpoint directories; each opens independent read-only index connections. Completed shard manifests include row ranges, counts, model/file checksums, and timings. Merge requires contiguous ranges and validates the exact match/candidate subset contract before publishing final TSVs.
